## 1. 背景与问题

「奇门排盘」目前是一个纯静态 PWA：浏览器打开网页，或通过「添加到主屏幕」近似原生。真实使用中存在四个痛点：

- P1 **不够像 App**：入口依赖浏览器/网址，主屏图标是快捷方式，卸载/清缓存后丢失，心理上不是「我的应用」。
- P2 **手机信息过载**：单页纵向堆了「四柱 + 九宫 + 克应 + 万年历 + 设局 + 案例」6 张卡片，手机上要长距离滚动，找东西靠翻。
- P3 **交付不可靠**：每次改动靠手工上传/手工验证，没有自动化回归，改动上线的信心来自「看起来没坏」。
- P4 **开发环境不敢碰**：安卓工具链动辄写入全局目录，这台多项目共用机器上没人愿意承担污染代价。

## 2. 目标用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 主人（专业使用者） | 起局、看盘、研判克应、存案例 | 一屏一件事、切换快、离线可用、数据不丢 |
| 主人（装机者） | 从 GitHub Release 下载 APK 安装 | 能装上、能覆盖升级、装完图标/名称正常 |
| 后续维护者（AI/人） | 改一行 UI 后发版 | 一条命令构建，CI 自动出包，失败信息可定位 |

## 3. 目标（Goals）

- G-1 产出可侧载安装的签名 release APK，覆盖 Android 7.0+（minSdk 24），断网可用。
- G-2 手机端改为 4 页分页（排盘 / 万年历 / 设局 / 案例），底部导航 + 左右滑动 + 返回键语义 + 页面记忆。
- G-3 安卓工具链 100% 项目内自包含，零全局写入（无 `~/.gradle`、`~/.android`、系统 SDK）。
- G-4 建立最小但真实的工程基线：结构测试、分页行为测试、产物校验、CI/CD、tag 触发自动发布。
- G-5 桌面网页版（GitHub Pages）行为与视觉不回归。

## 4. 非目标（Non-goals）

- 不上架应用商店；不做 iOS/鸿蒙；不做后端/账号/云同步；不改奇门算法与历法数据；不引入前端打包器；不做本机模拟器 E2E（硬件不支持）。

## 5. 用户故事与验收标准

### US-1 安装与启动
**作为** 主人，**我要** 从 GitHub Release 下载 APK 安装，**以便** 桌面上有一个独立应用。

- AC-1.1 Release 资产包含 `qimen-v<版本>.apk` 与 `SHA256SUMS.txt`，APK 大小合理（≤ 15MB）。
- AC-1.2 `apksigner verify` 通过；`aapt2 badging` 显示包名 `io.github.hhx465453939.qimen`、版本名与 tag 一致、label「奇门排盘」、minSdk 24、targetSdk 34。
- AC-1.3 APK 内 `assets/public/` 含 `index.html`、`css/style.css`、`js/app.js`、`js/qimen.js`、`js/calendar.js`、`js/database.js`、`js/raw_keying.json`、图标；**不含** `sw.js`。
- AC-1.4 首次启动直接进入排盘页，无白屏、无 `ERR_FILE_NOT_FOUND`、无 JS 未捕获异常（启动日志断言）。
- AC-1.5 飞行模式下冷启动仍可起局。

### US-2 手机分页
**作为** 手机用户，**我要** 一屏一页并可左右滑动，**以便** 快速找到「看盘 / 查历 / 设局 / 案例」。

- AC-2.1 小屏（≤900px）下 4 个页面互斥显示：`pan`（四柱+九宫+克应）、`cal`（万年历）、`setting`（设局控制）、`cases`（案例格局）。
- AC-2.2 底部导航点击切页，active 态同步；页面切换有可见过渡（≤250ms）。
- AC-2.3 左右滑动切页生效；起手位置在可横向滚动元素内或弹窗打开时不触发切页。
- AC-2.4 每页独立滚动，切页后目标页滚动位置恢复、页面自身回到上次位置。
- AC-2.5 安卓返回键优先级：关弹窗 > 回 `pan` 页 > 交系统退出；不允许「按返回直接退出而弹窗还开着」。
- AC-2.6 冷启动恢复上次所在页；URL hash（`#/pan` 等）与当前页一致。
- AC-2.7 桌面（≥901px）不启用分页：双栏布局、全部卡片可见、无横向位移、无隐藏卡片。

### US-3 环境自包含
**作为** 维护者，**我要** 工具链只在项目内，**以便** 不污染这台共用机器。

- AC-3.1 `npm run setup` 在 `.toolchain/` 内装好 JDK 21、Android SDK（platform-tools、platforms;android-35、build-tools;35.0.0）、Gradle 用户目录。
- AC-3.2 构建全程后，`~/.gradle` 与 `~/.android` **仍不存在**（脚本断言）。
- AC-3.3 删除 `.toolchain/` 后仓库仍可正常工作（`git status` 干净、网页版不受影响）。
- AC-3.4 工具链目录、`node_modules`、`www/`、`android/app/build` 均在 `.gitignore` 内，且 Android 图标 PNG **不被** 误忽略。

### US-4 自动化流水线
**作为** 维护者，**我要** push 即校验、打 tag 即发版，**以便** 不手工搬包。

- AC-4.1 push 到 `main` 触发：依赖安装 → 结构/行为测试 → web 构建 → `cap sync` → `assembleRelease`（有密钥则签名）→ 产物校验，任一失败即红。
- AC-4.2 打 `v*` tag 触发发布：创建 GitHub Release，附 APK + SHA256，release notes 含版本、最低系统、安装说明、签名指纹。
- AC-4.3 无签名 secrets 时流水线**不红**：降级产出 debug 签名 APK，并在 Job Summary 明确标注「未签名 release」。
- AC-4.4 版本号来自 tag：`versionName` = tag 去 `v`，`versionCode` 单调递增且可复现。
- AC-4.5 重复打同一 tag / 已有 Release 时，任务给出明确失败或幂等更新，不静默覆盖。

### US-5 质量门禁
**作为** 主人，**我要** 交付前有证据，**以便** 我只需做设备端确认。

- AC-5.1 `npm test` 全绿，覆盖：DOM 结构完整性、4 页映射、切页行为、返回键优先级、桌面不回归、资源引用存在性。
- AC-5.2 `npm run verify:apk` 输出 badging / 签名 / 资产清单 / 体积四项结论，任一不符即非零退出。
- AC-5.3 发布前自查清单全部勾选（见 SPEC §8 DOD），未勾选项必须写明原因。

## 6. 成功指标

| 指标 | 目标 |
|---|---|
| APK 可安装率（主人设备） | 首次安装成功，无需二次排障 |

| 手机切页操作步数 | 任意页 ≤ 1 次点击 |

## 10. 风险（产品视角）

见 CHANGE.md §8。产品侧需主人知晓的两条：
- R-1 签名密钥丢失 = 无法覆盖升级（数据在 WebView localStorage，卸载即丢）。
